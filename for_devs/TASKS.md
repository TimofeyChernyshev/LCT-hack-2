# Распределение задач проекта: Платформа-агрегатор ИТ-вакансий (ФСП)

> **Проект:** Цифровая платформа-агрегатор ИТ-вакансий с верифицированным профилем достижений участника Федерации спортивного программирования (ФСП)  
> **Команда:** 2 Backend разработчика, 1 Frontend разработчик  
> **Ключевой фокус ТЗ:** Обратная механика рекрутинга (LHH), скрытые контакты до оффера, обязательная вилка ЗП, античит-система тестирования, верификация через ФСП и прозрачная объяснимость рекомендаций.

---

## 👨‍💻 Backend Developer 1: Платформа, Бизнес-логика и Обратный подбор (LHH)

**Основная зона ответственности:** Ядро платформы, СУБД, безопасность (152-ФЗ), ролевая модель, маскирование контактов, жизненный цикл офферов/приглашений, API поиска и Docker.

### Задачи:

#### `[BE1-01]` Базовая инфраструктура, архитектура БД и контейнеризация
* **Приоритет:** Высокий (MVP)
* **Критерий ТЗ:** Техническая проработка (7%)
* **Описание:**
  * Развернуть каркас проекта (FastAPI / NestJS / Go / Django) с чистым разделением слоев (Service / Repository / Controller).
  * Настроить `docker-compose.yml` (Backend 1, Backend 2 / ML-сервис, Frontend, PostgreSQL, Redis).
  * Спроектировать и накатить миграции схемы БД:
    * `users`, `candidate_profiles`, `employer_profiles`, `specializations`, `grades`, `invitations`, `vacancies`, `audit_logs`.
  * Настроить автогенерацию Swagger / OpenAPI спецификации.
* **Критерии приемки (DoD):**
  * Проект поднимается командой `docker compose up --build`.
  * Эндпоинты `/docs` отдают актуальную OpenAPI-спецификацию.

#### `[BE1-02]` Аутентификация, роли и комплаенс 152-ФЗ
* **Приоритет:** Высокий (MVP)
* **Критерий ТЗ:** Безопасность и полнота (6%)
* **Описание:**
  * Регистрация и авторизация по email + пароль с подтверждением почты (JWT / сессии).
  * Разграничение прав по ролям (RBAC): `CANDIDATE`, `EMPLOYER`, `ADMIN`.
  * Архитектурный задел под будущую интеграцию с Keycloak (совместимость токенов/OAuth2).
  * Реализация фиксации согласия на обработку ПДн (152-ФЗ) и настройка параметров приватности профиля.
* **Критерии приемки (DoD):**
  * Неавторизованный пользователь и соискатель не имеют доступа к закрытым эндпоинтам работодателя и наоборот.
  * Сохраняется отметка о согласии с 152-ФЗ.

#### `[BE1-03]` Профиль соискателя и модуль приватности (Data Masking)
* **Приоритет:** Критический (MVP)
* **Критерий ТЗ:** Новая механика подбора (35%), Безопасность
* **Описание:**
  * CRUD профиля кандидата: ФИО, локация, специализация, грейд, стек технологий, опыт, зарплатные ожидания.
  * **Реализация маскирования контактов:** в публичной выдаче для работодателей контакты (email, телефон, Telegram, ссылки) строго скрыты или заменены на хеш/плейсхолдер.
  * Механизм динамического снятия маски: контакты раскрываются конкретному работодателю только после того, как кандидат нажал «Принять приглашение» (или сам откликнулся).
* **Критерии приемки (DoD):**
  * Ни один запрос от работодателя к базе/API не возвращает контакты кандидата до смены статуса инвайта на `ACCEPTED`.

#### `[BE1-04]` Профиль работодателя и API каталога кандидатов
* **Приоритет:** Высокий (MVP)
* **Критерий ТЗ:** Новая механика подбора (35%)
* **Описание:**
  * CRUD профиля компании: название, описание, стек, контакты рекрутера.
  * Эндпоинт описания потребности компании (сохранение фильтра: стек, специализация, грейд).
  * Эндпоинт поиска по банку кандидатов с фасетной фильтрацией (специализация, грейд, стек, наличие подтверждения ФСП) с пагинацией.
  * Сохранение состояния выборки при уточнении запроса.
* **Критерии приемки (DoD):**
  * Поиск отдает категоризированных кандидатов с рассчитанным рангом и обоснованием соответствия (данные ранжирования запрашиваются у модуля Backend 2).

#### `[BE1-05]` Жизненный цикл приглашений (Обратный подбор / LHH)
* **Приоритет:** Критический (MVP)
* **Критерий ТЗ:** Новая механика подбора (35%)
* **Описание:**
  * Эндпоинт отправки приглашения от работодателя кандидату:
    * **Обязательная валидация вилки ЗП:** поля `salary_min` и `salary_max` (в рублях) обязательны, `salary_min <= salary_max`.
    * Описание предложения, условия работы, способ связи.
  * Конечный автомат статусов взаимодействия:
    * `SENT` (отправлено) $\to$ `VIEWED` (просмотрено) $\to$ `ACCEPTED` (принято) / `REJECTED` (отклонено).
  * При `ACCEPTED`: автоматическая разблокировка контактов кандидата для работодателя.
  * Эндпоинты получения входящих инвайтов для кандидата и исходящих для работодателя.
* **Критерии приемки (DoD):**
  * Нельзя отправить оффер без вилки ЗП в рублях.
  * Обе стороны видят синхронный актуальный статус взаимодействия.

#### `[BE1-06]` Дополнительный функционал: Прямые вакансии и отклики
* **Приоритет:** Средний (Bonus / Доп. функционал 7%)
* **Критерий ТЗ:** Дополнительный функционал (7%)
* **Описание:**
  * Публикация вакансий работодателем (с обязательной вилкой зарплаты).
  * Возможность кандидата самостоятельно просмотреть вакансии и подать отклик.
  * Список входящих откликов для работодателя.
* **Критерии приемки (DoD):**
  * Классический сценарий отклика работает параллельно с основным обратным подбором.

## 👨‍💻 Backend Developer 2: Тестирование, Ранжирование, ФСП и Data/ML

**Основная зона ответственности:** Защищенная система тестирования (античит), логика присвоения грейдов, интеграция с реестром ФСП, скоринг кандидатов с объяснимостью (*XAI*), синтетический датасет и валидация.

### Задачи:

#### `[BE2-01]` Движок адаптивного тестирования и защита от списывания
* **Приоритет:** Критический (MVP)
* **Критерий ТЗ:** Механика тестирования (25%)
* **Описание:**
  * Спроектировать модель данных тестов: темы, уровни сложности (Junior, Middle, Senior), вопросы, варианты ответов, задачи с кодом/тест-кейсами.
  * Реализовать механизм защиты от утечки ответов:
    * Пул параметризованных шаблонов (случайная генерация числовых значений/структур кода).
    * Динамический банк вопросов с рандомизацией порядка и вариантов.
    * Ограничение по времени на каждый вопрос / тест.
  * API управления сессией тестирования: инициализация сессии, выдача вопросов по одному, прием ответов, автопроверка.
* **Критерии приемки (DoD):**
  * Кандидаты получают уникальные комбинации заданий одинакового уровня сложности.
  * Автоматический подсчет итогового балла и процента прохождения.

#### `[BE2-02]` Логика присвоения категории, грейда и кулдаун
* **Приоритет:** Высокий (MVP)
* **Критерий ТЗ:** Механика тестирования (25%)
* **Описание:**
  * Опросник на входе: определение специализации и заявленного грейда.
  * Логика изменения грейда по итогам теста:
    * При неуспешном прохождении — грейд не срезается принудительно «в ноль», предлагается сдать тест на уровень ниже.
    * При уверенном результате — возможность подтвердить или повысить грейд.
  * Механизм кулдауна смены грейда: ограничение повторной сдачи (например, таймер на 30/90 дней с записью даты последней попытки).
  * Фиксация присвоенной категории (`специализация + подтвержденный грейд`).
* **Критерии приемки (DoD):**
  * Категория кандидата жестко привязана к результатам теста, а не к его самоописанному резюме.
  * Повторная попытка блокируется до истечения кулдауна.

#### `[BE2-03]` Сервис интеграции с достижениями ФСП (Mock + Keycloak-ready)
* **Приоритет:** Высокий (MVP)
* **Критерий ТЗ:** Полнота реализации и ФСП (6%)
* **Описание:**
  * Разработать Mock-сервис реестра Федерации спортивного программирования.
  * Структура достижений: ID участника, разряд/рейтинг ФСП, участие в чемпионатах, победы в хакатонах, призовые места.
  * Эндпоинт связывания аккаунта платформы с `fsp_id`.
  * **Обработка краевого случая:** корректная работа профиля кандидата **без истории ФСП** (отсутствие ошибок, нейтральное состояние, базовый скоринг).
* **Критерии приемки (DoD):**
  * Профиль обогащается достижениями ФСП при наличии ID.
  * Для кандидатов без ФСП интерфейс и алгоритмы работают штатно и прозрачно.

#### `[BE2-04]` Алгоритм ранжирования в подборке и объяснимость (Explainable Ranking)
* **Приоритет:** Критический (MVP)
* **Критерий ТЗ:** Новая механика подбора (35%)
* **Описание:**
  * Разработать формулу ранжирования соискателей внутри категории:
    $$\text{Score} = w_{\text{test}} \cdot S_{\text{test}} + w_{\text{fsp}} \cdot S_{\text{fsp}} + w_{\text{stack}} \cdot S_{\text{stack}} + w_{\text{activity}} \cdot S_{\text{act}}$$
  * Формирование текстового обоснования выдачи для работодателя (*«Почему кандидат в топе»*):
    * Например: *«Топ-5% по результатам теста на знание Backend Python, серебряный призер Кубка ФСП 2025, полное совпадение по стеку: PostgreSQL, Redis»*.
* **Критерии приемки (DoD):**
  * Выдача кандидатов работодателю отсортирована по силе объективного профиля.
  * Каждый кандидат в выдаче содержит понятный JSON-блок с обоснованием ранга.

#### `[BE2-05]` Синтетический датасет и процедура валидации решения
* **Приоритет:** Высокий (Обязательно для сдачи)
* **Критерий ТЗ:** Валидация решения (25%), Документация (6%)
* **Описание:**
  * Скрипт генерации синтетического датасета:
    * 60–100 реалистичных кандидатов (разные грейды, стеки, баллы тестов, с достижениями ФСП и без).
    * 15–20 профилей работодателей и требований.
  * Проведение валидации алгоритма:
    * Проверка дискриминативности тестов (разделение сильных и слабых).
    * Оценка согласованности грейдов при повторном прохождении.
    * Метрики релевантности ранжирования (Precision@K / NDCG).
  * Выгрузка результатов в markdown/таблицу для презентации и сопроводительного отчета.
* **Критерии приемки (DoD):**
  * База данных инициализируется демо-данными одной командой сидинга (`seed.py`).
  * Сформирован отчет с графиками/метриками валидации.

#### `[BE2-06]` Дополнительно: Парсинг PDF-резюме и регулярные мини-задачи
* **Приоритет:** Средний (Bonus / Доп. функционал 7%)
* **Критерий ТЗ:** Функциональные требования, Бонусы (7%)
* **Описание:**
  * Модуль распознавания PDF резюме (извлечение стека, контактов, стажа через NLP/LLM) для автозаполнения профиля кандидата.
  * Генератор стандартизированного PDF-профиля кандидата.
  * Эндпоинты регулярных коротких задач от работодателя для поддержания активности профиля.
* **Критерии приемки (DoD):**
  * Загруженный PDF парсится и возвращает структурированный JSON с полями анкеты.

## 🎨 Frontend Developer: Личные кабинеты, UI/UX и Брендинг ФСП

**Основная зона ответственности:** Дизайн-система в стилистике ФСП, адаптивный интерфейс двух личных кабинетов (Кандидат и Работодатель), визуализация тестирования, каталог кандидатов и трекер офферов.

### Задачи:

#### `[FE-01]` Дизайн-система, брендбук ФСП и базовый легион UI
* **Приоритет:** Высокий (MVP)
* **Критерий ТЗ:** Удобство интерфейса (10%)
* **Описание:**
  * Развернуть проект (Next.js / React + Tailwind CSS / shadcn/ui).
  * Интегрировать брендбук ФСП: фирменные цвета (фиолетовый, синий, белый), шрифты, логотипы Федерации спортивного программирования.
  * Настроить глобальный лейаут: хедер с переключением ролей (для удобства демо жюри), нотификации, адаптивная верстка.
  * Клиентский роутинг с защитой приватных маршрутов (Role Guards).
* **Критерии приемки (DoD):**
  * Все экраны оформлены в единой аккуратной цветовой гамме ФСП с высокой контрастностью и читаемостью.

#### `[FE-02]` Авторизация, онбординг соискателя и 152-ФЗ
* **Приоритет:** Высокий (MVP)
* **Критерий ТЗ:** Функциональные требования, Удобство (10%)
* **Описание:**
  * Формы входа и регистрации с подтверждением email.
  * Чекбокс согласия на обработку ПДн (152-ФЗ).
  * Пошаговый визард заполнения профиля соискателя:
    * Ручной ввод данных либо область Drag-and-drop для загрузки PDF-резюме с индикатором автопарсинга.
    * Поле привязки ФСП ID.
* **Критерии приемки (DoD):**
  * Кандидат проходит регистрацию и первичную анкету без затруднений.

#### `[FE-03]` Интерфейс прохождения тестирования и подтверждения грейда
* **Приоритет:** Критический (MVP)
* **Критерий ТЗ:** Механика тестирования (25%), Удобство (10%)
* **Описание:**
  * Экран предварительного опроса: выбор направления/специализации и желаемого грейда.
  * Экран тестирования:
    * Таймер обратного отсчета времени.
    * Индикатор прогресса (вопрос N из M).
    * Карточки вопросов: тесты с вариантами ответов и блоки кода с подсветкой синтаксиса.
  * Экран итогов тестирования:
    * Наглядный статус присвоенной категории и грейда.
    * Бейджи верификации ФСП (если есть) или статус отсутствия истории.
    * Блок с таймером кулдауна до следующей возможной пересдачи грейда.
* **Критерии приемки (DoD):**
  * Интуитивный процесс тестирования, наглядное отображение полученной категории.

#### `[FE-04]` Личный кабинет соискателя: Инбокс приглашений и приватность
* **Приоритет:** Критический (MVP)
* **Критерий ТЗ:** Новая механика подбора (35%)
* **Описание:**
  * Дашборд соискателя: текущая категория, подтвержденный грейд, блок достижений ФСП.
  * Список входящих приглашений от работодателей:
    * **Акцентная плашка с вилкой ЗП («от — до» в рублях)** — кандидат сразу видит деньги.
    * Название компании, описание проекта/задач, контакты работодателя.
  * Кнопки действий: «Принять» / «Отклонить»:
    * Модальное предупреждение при принятии: *«Принимая оффер, вы открываете свои контакты работодателю X»*.
  * Статусы приглашений в реальном времени.
* **Критерии приемки (DoD):**
  * Соискатель видит только свои офферы; контакты работодателя видны сразу, вилка зарплаты выделена на первом плане.

#### `[FE-05]` Кабинет работодателя: Поиск кандидатов и объяснимость выдачи
* **Приоритет:** Критический (MVP)
* **Критерий ТЗ:** Новая механика подбора (35%), Удобство (10%)
* **Описание:**
  * Форма описания потребности команды (стек, специализация, грейд).
  * Витрина кандидатов с панелью фильтрации (грейд, специализация, стек, наличие ФСП).
  * Карточка кандидата в каталоге:
    * Категория, грейд, балл тестирования.
    * Спортивные награды и достижения ФСП.
    * **Блок объяснимости (Explainability):** бейдж *«Почему подходит»* с факторами попадания в топ.
    * **Блок замаскированных контактов:** плейсхолдер *«Контакты скрыты до подтверждения кандидатом»*.
* **Критерии приемки (DoD):**
  * Работодатель видит объективный профиль и объяснение ранжирования, но не имеет доступа к прямым контактам до отправки оффера.

#### `[FE-06]` Кабинет работодателя: Отправка оффера и Трекер взаимодействий
* **Приоритет:** Критический (MVP)
* **Критерий ТЗ:** Новая механика подбора (35%)
* **Описание:**
  * Модальное окно «Отправить приглашение кандидату»:
    * Поля: диапазон заработной платы (Обязательно: «от» и «до», ₽), описание роли, ссылка/канал связи.
    * Валидация полей на клиенте.
  * Трекер исходящих приглашений (Канбан-доска или статусная таблица):
    * Колонки: `Отправлено` $\to$ `Просмотрено` $\to$ `Принято` $\to$ `Отклонено`.
    * В карточках со статусом `Принято` — динамически появляются раскрытые контакты кандидата (Telegram, телефон, email).
* **Критерии приемки (DoD):**
  * Полный цикл: выбор кандидата $\to$ оффер с ЗП $\to$ ожидание $\to$ отображение открывшихся контактов.

#### `[FE-07]` Дополнительно: Доска вакансий соискателя и мобильная адаптивность
* **Приоритет:** Средний (Bonus / Доп. функционал 7%)
* **Критерий ТЗ:** Дополнительный функционал (7%)
* **Описание:**
